# 📋 피드백 요청사항 정리 (2026-05-18)

## ⓐ 세션 분리 + 세션 병합 방식 (가장 핵심) — 2026-05-18 설계 변경

**채택 방식: "세션 누적" 대신 "세션 병합"**
- 매 회차마다 **새 세션을 독립적으로 생성**해서 그 안에서 채점·분석 완결
- 여러 세션의 결과를 합산해야 할 때는 **세션 병합 뷰**에서 통계만 재계산해서 출력
- 즉, 원본 세션 데이터는 절대 변경되지 않고 박제됨

**왜 누적 방식 대신 병합 방식인가**
- **상태 단순화**: 각 세션은 완결 상태 → "지금이 어느 시점의 누적인가" 같은 모호함 없음
- **배부본 자동 보존**: 월요일에 강남 주중반에 배부한 통계가 토요일 이후에도 그대로 살아 있음 (누적 방식이면 다시 산출되어 값이 바뀜)
- **재채점 격리**: 한 세션에 문제가 생겨도 그 세션만 다시 돌리면 끝
- **운영 멘탈 모델과 일치**: 실제로 3번의 별개 시험 운영이니까 데이터도 3덩어리로

**실제 운영 시나리오 매핑**
| 회차 | 대상 | 시스템 동작 |
|---|---|---|
| 1회 | 강남 주중반 | **세션 1 생성** → 단독 채점/통계 → 응시자 배부 |
| 2회 | 강남 주말반 | **세션 2 생성** → 단독 채점 → **[세션 1 + 세션 2 병합 뷰]** 산출 → 응시자 배부 |
| 3회 | 종로 주말반 | **세션 3 생성** → 단독 채점 → **[세션 1 + 2 + 3 병합 뷰]** 산출 → 기획팀 전달 |

**구현 시 핵심 포인트**
- **시험지(문제·정답·배점)는 세션 간 공유**되어야 함 → "시험 템플릿" 개념으로 분리, 세션 생성 시 템플릿 선택
- **세션 병합 UI**: 같은 템플릿을 쓰는 세션들을 선택 → 합쳐진 모집단 기준으로 석차·표준점수·백분위 재계산
- **병합 뷰는 휘발성**(따로 저장 X, 출력만) 또는 **명시적으로 저장된 병합 결과**로 관리 — 후자가 자료 추적상 유리
- 단독 세션 리포트와 병합 리포트 양쪽 다 export 가능해야 함

**데이터 모델 변경 요지**
- `Exam(시험)` ↔ `Session(차수/반)` ↔ `OMR(응시자 답안)` 의 3계층 분리
- 통계 산출은 "선택된 세션 집합의 OMR을 모두 모은 모집단"에 대해 수행

## ⓒ 표준점수 스케일 사용자 설정 (재정의 — 2026-05-18)

**고객 의도 재해석**
- 원문: "중앙값/평균값이 100으로 설정되는 것" + "만점을 30점/40점으로도 할 수 있어야"
- 실제 요구: 표준점수의 **중심값(현재 100)과 단위(현재 20)** 을 시험마다 자유롭게 설정 가능하게
- 수능식(100/20)뿐 아니라 학원식(예: 30/5), 전통 T(50/10) 등 다양한 스케일 표시 필요

**코드 검증 결과 (2026-05-18)**
- `scoring.js:684, 700`: `tScore = ((X - μ) / σ) × 20 + 100` — 표준 T-Score 공식, 20/100 하드코딩
- 일괄 5점 배점과는 **무관** (배점이 무엇이든 정규화되어 평균=100으로 고정됨)
- 1차 수정으로 문항별 배점 입력 경로(`subjectMerge.js:117, 134, 143`)는 정상화됨

**구현 사양 (확정)**
- `× 20` 자리(scaleUnit, 표편) + `+ 100` 자리(centerScore, 평균) **둘 다** 사용자 설정 가능
- 설정 위치: **채점/결과 패널 상단** (실시간 재계산되어 결과 즉시 반영)
- 저장 위치: **세션 데이터에 포함** (세션마다 다른 스케일, 다시 열어도 유지)
- 기본값: 100/20 (수능식)

**구현 영향 범위**
- `scoring.js:684, 700` — tScore 계산식의 상수 → 세션 설정값 참조
- `scoring.js` — 채점 결과 패널 렌더링 코드에 스케일 입력 UI 추가
- `session.js` — 세션 저장/로드 시 `scoreScale: {center, unit}` 포함
- 변경 시 `calcStats` 재호출 + 패널 재렌더
