# 세션 병합 기능 — 데이터 모델 & 구현 설계서

> 작성: 2026-05-18
> 목적: ⓐ (피드백원함.md) 구현을 위한 청사진. 코드 짜기 전 검토용.

---

## 1. 현재 시스템 정리 (As-Is)

### 1-1. 기존 개념
| 개념 | 정의 | 저장 위치 |
|---|---|---|
| **양식(Template)** | OMR ROI 좌표 + 진하기 + 참조이미지만 담는 재사용 단위 | `{userData}/OMR_Data/templates/*.json` |
| **세션(Session)** | 한 회차 시험에 필요한 모든 것 (양식+과목+정답+인원+이미지+결과) | `{userData}/OMR_Data/sessions/{name}/{name}.json` + 이미지 디스크 |
| **양식 모드 세션** | `isTemplateMode=true` — 양식 편집 목적으로 만든 빈 세션 | sessions 폴더 안. `[양식]` prefix |

### 1-2. 현재 세션 데이터 스키마
```js
{
  sessionName, examName, examDate, isTemplateMode,
  subjects: [],         // 과목/정답/배점
  students: [],         // 응시 인원
  matchFields,
  answerKey,
  subjectMerges,
  scoreScale,           // 표점 스케일 (2026-05-18 추가)
  periods: [],          // 교시
  imageResults: [],     // OMR 답안 + 결과 (가장 큰 부분)
  deletedImageResults: [],
}
```

### 1-3. 현재 모델의 한계 (왜 ⓐ가 안 됨)
- **시험지 정의와 응시 데이터가 한 세션에 묶여 있음** → 같은 시험을 다른 반에서 또 치르려면 **모든 메타(과목/정답/배점)를 다시 입력**해야 함
- "양식" 개념은 ROI만 담아 시험지 메타는 공유 못 함
- 여러 세션의 통계를 합치는 메커니즘 없음 (모든 통계는 한 세션 내부에서만 계산)

## 2. 목표 모델 (To-Be)

### 2-1. 3계층 분리
```
Exam (시험지 정의)                              ← 한 번 만들면 재사용
├── id, name ('2026 6월 모의고사'), date
├── 양식(rois, intensity, 참조이미지)
├── subjects (과목/정답/배점)
├── periods (교시 구성)
├── answerKey
├── scoreScale (표점 스케일)
└── sessions: [Session 1, Session 2, Session 3, ...]
       │
       Session (한 회차 응시 데이터)            ← 반/지점/날짜별
       ├── id, name ('강남 주중반 04/15'), takenAt
       ├── examId (parent 참조)
       ├── attendanceBookId (출석부 참조, 옵션)
       ├── students (snapshot — 출석부 변경에 영향받지 않음)
       ├── matchFields
       ├── imageResults (이 세션 응시자들의 OMR만)
       └── deletedImageResults
```

### 2-2. 핵심 원칙
1. **Exam은 한 번 만들면 변경 거의 없음** (정답 수정 시만)
2. **Session은 응시 단위로 추가만 됨** — 완결되면 박제, 재계산 시에도 결과 안 변함
3. **통계는 항상 "선택된 Session 집합"에 대해 계산** — 단일 세션이든 다중 세션이든 동일 코드
4. **병합 뷰는 휘발성 또는 명시적 스냅샷** — 데이터 중복 최소화

### 2-3. 병합 뷰
- UI에서 같은 Exam의 N개 Session 체크 → 가상 모집단 생성
- 그 위에 `calcStats / calcItemAnalysis` 그대로 실행 (기존 로직 재사용)
- 산출물: 통계, 성적일람표, 문항분석표, 개인별 성적표 (모두 Session 단독 출력과 동일 양식)
- 옵션: "이 병합 결과를 스냅샷으로 저장" → `mergeSnapshots/`에 결과만 JSON으로 보관 (다음 회차 추가 후에도 과거 시점 결과 재현 가능)

## 3. 저장 구조 변경

### 3-1. 새 폴더 구조
```
{userData}/OMR_Data/
├── templates/                          (기존 유지 — 순수 양식)
├── sessions/                           (기존 유지 — 레거시 단일 세션, 점진 마이그레이션)
└── exams/                              (신규)
    └── {examId}/
        ├── exam.json                   (Exam 메타 + 양식 + 시험지 메타)
        ├── sessions/
        │   ├── {sessionId_1}/
        │   │   ├── session.json
        │   │   └── images/             (이미지 파일들)
        │   ├── {sessionId_2}/...
        │   └── {sessionId_3}/...
        └── mergeSnapshots/             (옵션, 명시 저장된 병합 결과)
            └── {snapshotId}.json
```

### 3-2. 신규 스키마
**`exam.json`**
```js
{
  id: 'exam_xxx',
  name, date, createdAt, updatedAt,
  version: 2,
  rois, intensity, referenceImage,     // 양식 부분
  subjects, periods, answerKey,
  subjectMerges, scoreScale,
}
```

**`session.json`** (Exam 하위)
```js
{
  id: 'sess_xxx',
  examId,
  name, takenAt,
  attendanceBookId,
  students, matchFields,
  imageResults, deletedImageResults,
  imageCount,
  gradedAt, savedAt,
}
```

## 4. 마이그레이션 전략

### 4-1. 기존 세션 호환성
- `sessions/` 폴더의 기존 세션은 **그대로 열림** (legacy 모드)
- 단, 신규 기능(병합 뷰)은 사용 못 함 → 화면에 "이 세션을 시험으로 변환" 버튼 노출

### 4-2. 자동 변환 흐름 ("시험으로 변환" 클릭 시)
1. 기존 `session.json`에서 시험지 메타(subjects/answerKey/scoreScale/periods/양식) 추출 → 새 `exam.json` 생성
2. 응시 데이터(students/matchFields/imageResults)는 새 Session 1개로 생성
3. 이미지 파일들은 새 위치로 이동
4. 기존 세션 폴더는 `_archived/` 로 백업 (즉시 삭제 X)

### 4-3. 신규 사용자 흐름
- "새 시험 만들기" → Exam 생성 + 첫 Session 자동 생성 (자연스러운 1세션 흐름)
- 같은 시험에 회차 추가 시 → "이 시험에 새 회차 추가" → Session만 추가됨

## 5. UI 변경 사항

### 5-1. 사이드바 / 시험 트리
- 기존 평탄한 세션 리스트 → **Exam 그룹 + 하위 Session 목록**
- 트리 노드 구조:
  ```
  📂 2026 6월 모의고사 (3세션)
     ├─ 📄 강남 주중반 (45명)        ← 현재 활성
     ├─ 📄 강남 주말반 (38명)
     └─ 📄 종로 주말반 (52명)
  ```

### 5-2. 채점 결과 패널 상단에 세션 선택기
- 현재 활성 세션 표시
- **"+ 회차 추가"** 버튼 (이 Exam에 새 Session 생성)
- **"세션 병합"** 버튼 → 체크박스 모달 → 선택된 세션 합쳐서 통계 표시

### 5-3. 병합 뷰 표시
- 패널 상단에 노란 배경 배너 "병합 뷰: 강남 주중 + 강남 주말 (총 83명)"
- 모든 표는 동일 (calcStats/calcItemAnalysis가 합쳐진 모집단으로 동작)
- "스냅샷 저장" / "단독 세션으로 돌아가기" 액션

### 5-4. 출석부 연동 (ⓓ와 직접 연결)
- 새 Session 생성 시 → 출석부 선택 다이얼로그 자동 표시
- 같은 Exam의 이전 Session에서 쓴 출석부를 기억해서 "동일 출석부로 시작" 단축 옵션 제공

## 6. 통계 재계산 파이프라인

### 6-1. 현재 흐름
```
Scoring.collectData() → rows (단일 세션의 모든 응시자)
   ↓
Scoring.calcStats(rows) → tScore/rank/percentile 계산
Scoring.calcItemAnalysis(rows, subj) → 문항분석
```

### 6-2. 변경 후 흐름
```
SessionSet (활성 세션 ID 목록) → ExamHub.collectMergedRows(sessionIds)
   ↓ (여러 세션의 응시자 + answers 한 배열로 통합)
Scoring.calcStats(mergedRows) ← 코드 변경 없음, 입력만 더 큼
Scoring.calcItemAnalysis(...) ← 동일
```

**핵심**: Scoring 모듈은 입력이 어디서 왔는지 모르고 동작 → 변경 최소

### 6-3. 주의점
- 표점은 합쳐진 모집단의 평균/표편 기준으로 재계산 → 각 세션 단독 표점과 다름 (정상)
- 응시자 키(이름/수험번호)가 세션 간 충돌하면 자동으로 세션 이름 prefix
- `scoreScale`은 Exam 단위로 고정 (모든 Session 공통)

## 8. 결정 사항 (2026-05-18 확정)

1. **출시 방식**: **Phase별 PR로 점진 출시** — Phase 1 완료 후 검증 → 다음 Phase
