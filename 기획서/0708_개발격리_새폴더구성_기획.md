# 성능개선 작업 격리를 위한 새 폴더 구성 기획 (2026-07-08)

> **상태**: 계획 수립 · 실행 대기
> **목적**: 사용자가 현재 폴더(`NEW_OMRGRADING`)로 실제 채점 업무를 계속 진행해야 하므로, `0708_대용량배치_성능개선_기획.md`의 수정 작업(원인 C→D→A→B)은 **완전히 별도의 새 폴더**에서 진행하고 기존 폴더는 절대 건드리지 않는다.

---

## 왜 "폴더만" 분리해서는 부족한가

코드를 통째로 복사해 새 폴더에서 `npm start`로 띄우면 코드는 격리되지만, **저장 데이터 경로는 격리되지 않을 수 있다.** 확인 결과:

`main.js:62~66`
```js
function getAppDataPath() {
    const appData = app.getPath('userData'); // Electron이 app 이름 기준으로 자동 결정
    const omrPath = path.join(appData, 'OMR_Data');
    ...
}
```

Electron의 `app.getPath('userData')`는 **`package.json`의 `name`(또는 `productName`)을 기준으로 OS의 사용자 데이터 폴더 경로를 만든다.** 지금 `package.json`의 `name`은 `"omr-grading-system"`이다.

→ 새 폴더에 코드를 그대로 복사해서 실행하면, `package.json`의 `name`이 동일하므로 **세션(exam) 데이터, 양식(template) 데이터가 저장되는 실제 경로(`%APPDATA%\omr-grading-system\OMR_Data\...`)가 기존 앱과 완전히 똑같은 폴더를 가리킨다.** 즉 겉보기엔 "새 폴더"지만, 실제 시험 데이터를 저장/조회하는 곳은 원본 앱과 공유된다 — 새 폴더에서 실수로 세션을 지우거나 덮어쓰면 **원본 앱에서 쓰던 실제 데이터도 같이 사라진다.**

**따라서 이번 작업은 반드시 다음 두 가지를 함께 분리해야 한다:**
1. 코드 폴더 (파일 시스템 경로)
2. 앱 데이터 저장 경로 (`userData`, `package.json`의 `name`으로 결정됨)

---

## 실행 계획

### 1단계 — 새 폴더에 코드만 복사 (무거운 샘플/참고자료 제외)

프로젝트 루트가 2.5GB인데 대부분은 실행에 필요 없는 샘플 이미지/참고자료(`Final/`, `_extracted_from_exe/`, `참고자료/`, `로스쿨샘풀/`, `설치용파일/`, `보고용/`, `1차보고/`, `devlog/`, `sample/`, `오엠알 스캔/`, 루트의 개별 jpg/png/zip 등)다. 새 폴더에는 앱 실행에 필요한 코드만 복사한다.

```powershell
$src = "C:\Users\admin\Documents\이민범 개발\NEW_OMRGRADING"
$dst = "C:\Users\admin\Documents\이민범 개발\NEW_OMRGRADING_성능개선"

robocopy $src $dst /E /XD `
    "$src\node_modules" "$src\.git" "$src\Final" "$src\_extracted_from_exe" `
    "$src\참고자료" "$src\로스쿨샘풀" "$src\설치용파일" "$src\보고용" `
    "$src\1차보고" "$src\devlog" "$src\sample" "$src\오엠알 스캔" "$src\dist" `
    /XF "*.zip" "*.jpg" "*.jpeg" "*.png" "*.csv"
```
(코드 파일: `main.js`, `preload.js`, `index.html`, `js/`, `css/`, `package.json`, `package-lock.json`, `icon.png`, `기획서/` 등만 복사됨)

### 2단계 — 앱 이름을 다르게 지정해 데이터 저장 경로 분리

새 폴더의 `package.json`에서 `name`을 변경:
```json
{
  "name": "omr-grading-system-dev",
  ...
}
```
그리고 `main.js`에 아래 한 줄을 `createWindow()` 호출 전에 추가해 확실하게 고정:
```js
app.setName('omr-grading-system-dev');
```
이렇게 하면 새 폴더 앱의 `userData` 경로가 `%APPDATA%\omr-grading-system-dev\...`가 되어, 원본 앱(`%APPDATA%\omr-grading-system\...`)과 완전히 분리된다. **세션/양식 데이터가 서로 절대 섞이지 않는다.**

### 3단계 — 창 제목으로 육안 구분 (실수 방지용 안전장치)

`main.js`의 `title: 'OMR 채점 시스템'` (line 13)을 새 폴더에서만:
```js
title: 'OMR 채점 시스템 [성능개선 개발용]',
```
로 바꿔서, 두 앱을 동시에 띄워놓고 작업해도 창 제목만 보고 바로 구분 가능하게 한다.

### 4단계 — 의존성 설치

복사본에는 `node_modules`를 포함하지 않았으므로:
```powershell
cd "C:\Users\admin\Documents\이민범 개발\NEW_OMRGRADING_성능개선"
npm install
```

### 5단계 — 격리 검증

1. 새 폴더에서 `npm start` 실행 → 창 제목에 "[성능개선 개발용]" 표시되는지 확인
2. 새 폴더 앱에서 세션 1개 저장 → 탐색기에서 `%APPDATA%\omr-grading-system-dev\OMR_Data\sessions\`에 생기는지 확인 (기존 `%APPDATA%\omr-grading-system\OMR_Data\sessions\`에는 아무것도 안 생겨야 함)
3. 기존 앱(원본 폴더)을 동시에 띄워서 두 창이 독립적으로 동작하는지(한쪽에서 저장해도 다른 쪽 목록에 안 보이는지) 확인

## 이후 작업 흐름

1. 새 폴더(`NEW_OMRGRADING_성능개선`)에서 `0708_대용량배치_성능개선_기획.md`의 **원인 C → D → A → B** 순서대로 코드 수정 및 테스트 진행
2. 실제로 언어_통합/추리_통합(각 ~962장) 데이터로 새 폴더 앱에서 업로드→일괄분석→교정탭→결과표까지 전체 흐름을 검증
3. 문제없이 확인되면, 수정된 파일들(`batch.js`, `imageManager.js`, `canvas.js`, `correction.js`, `scoring.js`)만 원본 폴더에 반영 — 이때는 사용자가 원본 폴더 작업을 잠시 멈춘 시점에 git으로 정식 반영 (새 브랜치 → PR/커밋 형태 권장)
4. 원본 폴더의 `package.json`(`name: omr-grading-system`)은 그대로 유지 — 데이터 경로는 절대 안 바뀜

## 참고 — git과의 관계

`robocopy`로 복사하면서 `.git`을 제외했기 때문에 새 폴더는 **git 이력이 없는 순수 코드 스냅샷**이다. 새 폴더에서 별도로 `git init`을 하든, 그냥 파일만 두고 작업하든 자유롭게 선택 가능 (원본 저장소의 커밋 히스토리와 전혀 얽히지 않으므로 원본 repo에 영향 없음). 나중에 반영 시에는 원본 폴더에서 새 브랜치를 만들어 수정된 파일을 옮겨 담고 정식 커밋하는 방식을 권장한다.

## 결론

- **"완전 새로운 폴더"** 요청은 코드 복사만으로는 부족하고, Electron 앱 이름(`package.json`의 `name`)까지 바꿔서 **데이터 저장 경로(userData)도 함께 분리**해야 원본 앱이 쓰는 실제 시험 데이터에 전혀 영향이 없다.
- 위 5단계(코드 복사 → 앱 이름 변경 → 창 제목 변경 → npm install → 격리 검증)를 거치면, 사용자는 원본 폴더의 기존 앱으로 실제 채점 업무를 계속하면서, 새 폴더의 개발용 앱으로 성능개선 작업(원인 C→D→A→B)을 안전하게 병행할 수 있다.
